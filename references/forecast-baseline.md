# 规则序列预测基线与滚动验证：M06方法卡

## 何时使用及知识依赖

用于一个实体的规则日/周观测销量或销售额，目标是建立朴素与季节朴素基线，核对历史留出误差。依赖可信粒度/覆盖、时间序列频率与季节长度依据、未来预测跨度及业务单位。缺货销量不能直接称潜在需求；需求识别、干预响应或补货最优需要另外的数据和业务约束，不从预测误差跳到行动收益。

## 输入契约 v1

固定脚本：[forecast_baselines.py](../scripts/forecast_baselines.py)。输入JSON必须包含以下字段，无未知字段或重复JSON键，数值有限。

| 字段 | 语义 |
| --- | --- |
| schema_version | 字符串`1` |
| source_ref / definition_ref / entity_ref / unit | 实际来源/口径/实体/单位引用，均为非空字符串 |
| target | 当前只支持`observed_sales`；不支持潜在需求/干预响应 |
| cutoff | 最后一个完整观测期的标签，YYYY-MM-DD；由实际来源覆盖核验，不是系统今天 |
| frequency_days | 正整数，期标签间经过日数；日=1，周=7。月份或不规则经营日不以固定天数冒充 |
| season_length | 正整数，业务确认的季节周期，以观测期计。脚本不从全样本搜索最优季节 |
| horizon | 正整数，真实要预测的期数，也是每个回测窗口的跨度 |
| backtest_windows / step_size | 正整数，滚动窗口数及起点间隔的观测期数；首个训练段须至少有season_length个观测，这只是算法可算条件，不证明数据充分 |
| observations | 时间正序、唯一、固定间隔，并完整到cutoff；每行仅date、value、stockout，stockout为布尔或null；来源没有缺货状态时填null，不能用false表示未知 |

value为实际数值或null；null返回unsupported，不能无依据补零。缺期/重复/倒序/截止后观测返回error，不悄悄改范围。输入是单一当前快照；未提供每个历史时点的实际可得快照，因此无法验证历史修订、补录或当时刷新完整性。

## 固定计算与验证

从Skill目录执行：

```bash
python3 scripts/forecast_baselines.py /absolute/path/normalized-series.json
```

朴素预测重复训练段最后一个观测；季节朴素循环重复训练段最后一个完整季节。每个回测起点仅用该点之前的值，预测相同horizon，并与之后实际对比；不使用外生变量，不调参，不自动选冠军。

输出：未来期标签、两种方法逐期预测、每个窗口的训练截止/预测/实际、相同起点和目标对上的MAE、逐跨度MAE及偏差（预测减实际）。窗口可能重叠，预测起点—目标对数不是独立样本数；不能据此直接做显著性判断。

所有结果标记backtest_kind=retrospective_current_snapshot，historical_as_of_availability_verified=false。这是当前快照上的顺序回测，不能声称已经证明真实历史时点可用性或无全部类型泄漏。prediction_intervals和selected_model均为null；不得自行补95%区间或称最优模型。

## 结果与停止边界

- ok/退出0：两种基线及回测完成，解释范围限于实际输入和被测跨度。
- unsupported/退出2：历史不够、缺值、未覆盖截止或目标不支持；输出具体原因，不返回伪预测。
- error/退出1：字段/格式、日期、数值错误或数值范围溢出；结构化JSON输出，不消费错误数值。
- stockout=null保留缺货未知并告警；可预测已观测销售，不确认需求或可售覆盖。
- stockout=true允许分析已观测销售并告警，不反推潜在需求；要做需求/补货需另取输入和业务约束。
- 趋势、变化点和未来促销可能使这两种基线很差；诚实报告误差与业务限制，不承诺基线达到项目精度要求。实际高级模型需另接已有合格引擎并同窗口比较，优先复用宿主已有实现。

生产使用需验证实际数据适配与业务用途；本基线不包含特征工程、外生变量模型或生产预测服务。
